API reference

moongguf

One package. Files, metadata tables, tensor indexes and the bytes behind them, with a refusal for everything that is not a GGUF file.

Written from pkg.generated.mbti and the source comments on every build: 82 public names, in three groups.

structFile

A GGUF file: the header, the metadata table, the tensor index, and — when the bytes of the data section were handed over with the rest — the tensor data itself. Reading never copies the tensor bytes. data hands out a view into the bytes the file was parsed from, so a gigabyte model costs its metadata and no more. A file too large for one Bytes is read in two parts: the index from the head of the file, and each tensor's bytes as they are needed, which shard takes a view of.

pub struct File {
  • // private fields
pub fn File::add(Self, Tensor, BytesView) -> Unit raise Refused

Put a tensor into the file, with its bytes. The bytes stay where the caller put them: a file holds views, and writing it copies them out once. The tensor lands at the end of the data section, where the one before it ends and the alignment is satisfied.

pub fn File::add_index(Self, Tensor) -> Unit raise Refused

Put a tensor into the file's index without its bytes, for a caller that writes the data section itself.

pub fn File::alignment(Self) -> UInt32

The alignment the data section starts on, from general.alignment or the format's default of 32.

pub fn File::data(Self, StringView) -> BytesView?

The bytes of a tensor, as a view into the bytes the file was parsed from. None when those bytes are not in hand — a file parsed from its index alone still answers everything about the tensor except its data.

pub fn File::data_start(Self) -> Int64 raise Refused

Where the data section starts: the end of the index, rounded up to the alignment. A file that was read knows this from its own bytes. A file built here finds it by writing its index, which is what a caller streaming a large file needs before it can place the first tensor.

pub fn File::encode(Self) -> Bytes raise Refused

The whole file: the index, then every tensor's bytes at the offset the index recorded, each followed by the zeroes that reach the alignment. One Bytes holds the result, so a file past what a Bytes can hold is refused rather than truncated: encode_index and add_index are there for writing such a file in pieces.

pub fn File::encode_index(Self) -> Bytes raise Refused

The index as bytes: the header, the metadata table, the tensor index, and the zeroes that bring the length up to the alignment. This is the first part of a file, and all of it a reader needs to answer what a model holds without its weights.

pub fn File::extent(Self, StringView) -> Extent raise Refused

Where a tensor's bytes sit and how far they run.

pub fn File::get(Self, StringView) -> Value?

The value under a metadata key.

pub fn File::header(Self) -> Header

The magic, the version and the two counts.

pub fn File::meta(Self) -> Meta

The metadata table.

pub fn File::new(alignment? : UInt32) -> Self

An empty version 3 file, ready for metadata and tensors to be put into it. An alignment other than the format's 32 is recorded as general.alignment, because a reader would otherwise lay the data section out at 32 and find every tensor's bytes in the wrong place.

pub fn File::order(Self) -> ByteOrder

The byte order the file's numbers are stored in.

pub fn File::parse(BytesView, limits? : Limits) -> Self raise Refused

Read a file from its bytes. The bytes may be the whole file, or just as much of it as holds the index — the header, the metadata table and the tensor index. Tensor bytes are only needed when something asks for them.

pub fn File::remove(Self, StringView) -> Unit

Drop a metadata key. Dropping general.alignment puts the alignment back to the format's 32.

pub fn File::set(Self, String, Value) -> Unit raise Refused

Put a value under a metadata key, replacing one already there. general.alignment is the one key with a meaning beyond its value: setting it moves where the data section starts, so the tensors after it move too. Only a power of two fits.

pub fn File::shard(Self, StringView, BytesView, at? : Int64) -> BytesView raise Refused

A view of a tensor's bytes read from somewhere else — the second half of reading a file too large for one Bytes, where the caller holds the data section in pieces. at is how far into the tensor the piece starts, so a tensor larger than one Bytes can be handed over in pieces of whatever size the caller can hold. The piece is checked against the tensor's extent and the part that belongs to the tensor is returned, padding and all dropped.

pub fn File::tensor(Self, StringView) -> Tensor?

One tensor's index entry.

pub fn File::tensor_count(Self) -> Int32

How many tensors the index holds.

pub fn File::tensors(Self) -> ArrayView[Tensor]

The tensor index, in file order.

pub fn File::to_json(Self) -> @json.Json
pub fn File::version(Self) -> Version

The version the file is written in.

enumGgmlType

The encodings a tensor's blocks can be stored in, numbered as ggml numbers them. The number is what a file stores, so an encoding keeps its number; a file that names a number outside this table is refused rather than guessed at. Reading a tensor's bytes is all this library does. Turning a block of q6_k into floats is arithmetic, and lives elsewhere.

structLimits

Ceilings on what a file may ask of a reader, so that a corrupt or hostile length cannot ask for gigabytes before the bytes behind it turn up. Each has a name and a published preset, so a caller reading files it did not make can tighten one without guessing at the rest. Going past one is Refused, carrying the ceiling and the number that went past it.

enumValue

One metadata value, as the file holds it. The integer kinds keep their width: a count stored as uint32 reads back as UInt32 and is written as uint32 again, so a file survives a round trip unchanged even where two widths could hold the same number. Array carries the kind its entries share, which an empty list would otherwise lose, and its entries may themselves be Array.
